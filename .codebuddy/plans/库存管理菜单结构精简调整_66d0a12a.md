## 用户需求

调整「库存管理」一级菜单下的二级目录结构：

1. 删除「备品备件管理」二级目录（其下三个三级入口全部迁移或删除）
2. 「库存查询」与「安全库存预警」合并为新的二级目录「库存查询与预警」（库存查询是查询所有物料库存的全局功能，不适合挂在备品备件下）
3. 彻底删除「备件领用」：移除菜单入口、删除 sp-pick.js 文件及其数据变量（功能已整合进领料单，历史领用数据不再可访问）
4. 调整后「库存管理」下共 5 个分组：物料主数据、库存查询与预警、预留单据、库存记账、采购申请管理

## 核心功能

- 菜单结构重组：删除「备品备件管理」分组，新增「库存查询与预警」分组（含库存查询、安全库存预警两个入口）
- 备件领用功能彻底下线：菜单、脚本引用、调试页引用、文档记录全部移除
- 其余入口（物料主数据、预留单据、库存记账、采购申请管理）保持不变

## 技术方案

基于现有 V3 纯 JS + HTML 架构（无构建工具），仅调整菜单配置与文件引用，不引入新依赖。

### 修改要点

1. **菜单配置** `V3/js/main.js`：

- 删除 `menu` 中「备品备件管理」分组对象（含 `sp-stock`、`sp-pick`、`safety-stock-alert` 三个 items）
- 新增「库存查询与预警」分组：`{ id:'sp-stock', label:'库存查询', route:'sp-stock' }` 与 `{ id:'safety-stock-alert', label:'安全库存预警', route:'safety-stock-alert', pageObj:'SafetyStockAlert' }`，位置置于「物料主数据」之后、「预留单据」之前
- `pageMap` 删除 `'sp-pick': SpPick,` 注册行
- `navigateGItem` 通过 `pageMap[route]` 解析页面对象，sp-stock 与 safety-stock-alert 的 pageMap 注册保持不变，无需其他改动即可正常导航

2. **脚本引用清理**：

- `V3/main.html` 删除 `<script src="js/pages/sp-pick.js"></script>`（第 578 行）
- `V3/debug.html`：files 数组删除 `'js/pages/sp-pick.js',`（第 25 行），vars 数组删除 `'spPickData','spPick',`（第 57 行）

3. **文件删除**：删除 `V3/js/pages/sp-pick.js`

4. **文档同步**：

- `V3/docs/ui-layout-spec.md` 第 174 行删除 sp-pick.js 合规清单行
- `V3/车间领退料与库存记账PRD.md` 第 54 行更新保留说明：改为「库存查询与预警（库存查询/安全库存预警）」，注明备件领用已删除、功能并入领料单

### 依赖与边界（关键）

- `sparePartsStockData`（定义于 spare-parts-stock.js）被 `sp-purchase.js`（聚合）与 `safety-stock-alert.js`（聚合）使用，**保留** spare-parts-stock.js 与 safety-stock-alert.js 不动
- `SafetyStockAlert` 被 `sp-purchase.js` 引用（安全库存/物料类型辅助方法），**保留**
- `SpPick`/`spPickData` 仅被 main.js、sp-pick.js、debug.html 引用，删除安全，无其他调用点
