## 产品概述

优化库存查询页面「显示类型」选项为三个层级，并实现选「工厂层级」时筛选条件的联动控制。

## 核心功能

- 「显示类型」三个选项按层级从粗到细重新排列，文案如下：

1. 工厂层级
2. 工厂+库存地点（批次汇总）—— 默认选中
3. 工厂+库存地点+批次（明细）

- 永久删除「库存类型」查询条件（非限制使用/质检中/冻结），三个档位均不再显示
- 选「工厂层级」时，查询区联动：库存地点下拉置灰、WBS编号输入框置灰、批次输入框隐藏
- 切回其他档位时恢复：库存地点/WBS 可用、批次重新显示
- 切换显示类型时清空工厂层级下无效条件的残留值，避免脏数据参与查询
- 显示类型切换沿用现有交互（切换后点「查询」生效），不改变查询/重置/分页等既有行为

## 技术栈

- 原生 HTML + 原生 JS（页面对象模式），无框架、无新依赖
- 唯一修改文件：`V3/js/pages/spare-parts-stock.js`

## 实现方案

本次为同一文件内的展示层与筛选联动微调，内部 value 标识（`plant`/`summary`/`batch`）全部保留，聚合逻辑（`_aggregate`/`_aggregateByPlant`）与表格渲染三分支零改动，杜绝回归风险。

### 1. 显示类型下拉重排（第 71-75 行）

```html
<div class="filter-group"><label>显示类型</label><select id="spDisplayType" onchange="SparePartsStock.onDisplayTypeChange()">
  <option value="plant">工厂层级</option>
  <option value="summary" selected>工厂+库存地点（批次汇总）</option>
  <option value="batch">工厂+库存地点+批次（明细）</option>
</select></div>
```

- 顺序由原「summary→plant→batch」调整为「plant→summary→batch」，与用户层级描述一致
- 默认选中保持 `summary`，与 `reset()` 重置值一致

### 2. 删除「库存类型」条件

- 删除第 78-83 行 `spStockType` 整个 filter-group DOM
- `search()`（第 285、294-297 行）：删除 `spStockType` 读取及非限制/质检/冻结三个过滤分支
- `reset()`（第 315 行）：删除 `document.getElementById('spStockType').value = ''`（DOM 已不存在，保留会报错）

### 3. 筛选条件联动（新增逻辑）

- 给批次 filter-group 加 `id="spBatchGroup"`，便于整组隐藏
- 新增 `_syncFilterStates()`：读取当前 `spDisplayType`，`plant` 档时设置 `spStorageLoc.disabled = true`、`spWbsNo.disabled = true`、`spBatchGroup.style.display = 'none'`；其他档位恢复 `disabled=false`、`display=''`
- 新增 `onDisplayTypeChange()`：仅在切换到 `plant` 时清空 `spStorageLoc`/`spWbsNo`/`spBatch` 的值（disabled 控件 value 仍可被读取，必须清空避免残留值参与查询），随后调用 `_syncFilterStates()`
- `init()`（第 116-123 行）与 `reset()`（第 309-321 行）末尾调用 `_syncFilterStates()`，保证初始与重置后状态正确

## 实现注意事项

- 置灰使用原生 `disabled` 属性（浏览器默认置灰样式），隐藏批次用 `display:none`，不新增 CSS
- 切换显示类型不自动触发查询，保持现有「切换→点查询」交互，避免行为突变
- 不影响 `renderTable()` 的图例显隐、次要字段展开按钮等既有逻辑
