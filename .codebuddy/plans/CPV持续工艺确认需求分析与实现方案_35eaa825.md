## 产品概述

基于客户提交的《基于SAP系统的持续工艺确认数据管理需求》，产出一份**中立的、可决策的**分析方案文档（Markdown，置于项目根目录），回答三件事：需求到底是什么、要在 SAP 里实现哪些能靠标准功能、哪些必须开发或借助外围系统、若改用自研 MES 承载则需与 SAP 打通哪些接口。

## 核心内容

- **需求梳理与拆解**：将原文 5 大章节（基础数据配置、数据采集录入、分析趋势监控、报告生成归档、权限安全）拆为可编号的需求点（R1…Rn），逐条对应到 SAP 术语与业务对象；同时识别文档未言明的关键缺口（控制上下限如何确定与维护、批号与工序的对应关系、定性指标只出文字结论、工艺参数范围写法不规范、偏差变更数据来源等）。
- **我们系统要做哪些工作**：按 CPV 全生命周期（主数据 → 采集 → 分析预警 → 报告归档 → 权限合规）列出工作包清单，每项标注输入、产出、依赖。
- **SAP 实现路线判定表**：逐条判定为「标准功能直接覆盖」「需 ABAP 开发/配置增强」「需借助外围系统（LIMS / 电子批记录 / DCS / BW-SAC / DMS）」三类，并给出判定依据。
- **自研 MES 实现路线**：MES 端新增功能模块与页面清单、数据表设计要点、以及与 SAP 的接口清单（接口名、方向、触发时机、关键字段、对应 SAP 标准 BAPI/RFC/CDS、失败与重试策略），接口风格与现有 `V3/js/core/sap-mock.js` 方法签名保持一致。
- **方案对比与待确认清单**：两方案在覆盖度、合规与审计追踪、实施周期、成本、变更灵活性、数据一致性、验证负担等维度中立并列，给出各自适用条件；结尾附「待用户确认事项」。

## 实施策略

以「需求点 → SAP 业务对象 → 判定结论」为分析主线，采用**三列判定法**：每条需求点必须落到「标准 / 开发 / 外围」三类之一，并给出依据，杜绝笼统结论。

### 判定依据（已核实的 SAP 标准能力边界）

| 需求域 | 可标准覆盖 | 需开发/配置 | 需外围系统 |
| --- | --- | --- | --- |
| CPP/KPP/CQA 主数据与控制区间 | CQA 规格上下限可由 QM 主检验特性（QS21）+ 检验计划（QP01/QP02）承载；工艺参数可挂工艺路线/生产版本 | **CPV 专属控制上下限（如收率 45~52%）SAP 无标准字段**，需自定义表/客户字段 + 维护界面 | — |
| 生产批次/时间/报工 | PP-PI 流程订单（COR1/COR3）、工序确认（COR6N，表 AFRU）、批次主数据 | — | 参数本身来自纸质批记录/DCS，标准不产生 |
| 工序收率 | 具备投料/产出数据基础（生产订单确认 + 货物移动 MSEG） | **「按投料与产出计算工序收率并形成 CPV 台账」需自开发** | 上游称量/投料系统可提高自动化率 |
| 检验结果（CQA） | QM 检验批结果记录（QALS/QAMR，QA32/QE51） | — | **LIMS / 电子批记录 EBR** 是自动采集前提 |
| 趋势图与超限预警 | QM 控制图（SPC）、质量通知（Q1）可做单点告警 | 多参数月度/季度趋势图、长期波动与季节性分析需自开发 | BW / Embedded Analytics / SAC 或 BI 平台 |
| 报告生成 | 输出管理与表单技术（Adobe Form/Smart Form）、DMS 归档（CV01N/DC10） | **CPV 报告模板与自动生成需自开发**（含 12 张趋势图附表的排版与结论文字） | 可选非 SAP 报表/文档平台 |
| 权限与账号 | 角色权限（PFCG/SU01/SUIM）一人一号、分级授权 | — | — |


**核心结论**：SAP **不存在标准「CPV 业务对象」**，即便走 SAP 路线，主体工作量仍落在自建一组自定义表 + ABAP/CDS/Fiori 应用上；纯标准功能只能覆盖权限、批次/报工/检验批数据底座与文档归档。

### 自研 MES 路线（与现有资产对齐）

- MES 端新增业务域「质量管理 → 持续工艺确认（CPV）」，与现有 `inspection-*`（主检验特性/检验方法/检验计划/检验批）形成上下游关系（检验计划/检验批提供 CQA 标准与结果）
- 接口层扩展方式：在 `V3/js/core/sap-mock.js` 中**按现有方法签名风格新增方法**（对接真实后端时仅替换本文件实现），不改变既有方法
- 需从 SAP 读取：流程订单与工序（COR3 / AUFK/AFKO/AFPO）、工序确认（AFRU）、货物移动（MSEG/MKPF）、检验批与检验结果（QALS/QAMR）、检验计划与主检验特性（PLKO/PLPO/PLMK）、批次特性（已有 `getBatchChars`）
- 需回写 SAP：原则为**不回写检验结果**（避免双重真相），仅按需将 CPV 报告归档至 SAP DMS
- 数据表建议：`cpv_param_master`（CPV 参数主数据+控制上下限）、`cpv_batch_scope`（确认周期/车间/工序/批次范围）、`cpv_param_value`（按批次参数值+来源标记）、`cpv_alarm`（超限预警）、`cpv_deviation_change`（偏差及变更汇总）、`cpv_report`（报告与归档）、`cpv_audit_log`（审计追踪），字段风格参考 `MES系统数据字典.xlsx`
