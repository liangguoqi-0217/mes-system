## 需求概述

仓库中存在若干库位权限不下放给 MES 系统（存放保密物资），不允许任何人在系统中知晓其库存数量。库存查询页所有展示入口（库位筛选下拉、库位汇总档、批次明细档、工厂层级汇总档）都不得暴露保密库位。

## 核心功能

- **完全不可见**：库位筛选下拉不出现保密库位选项；库位汇总/批次档不显示保密库位行；工厂层级汇总总量排除保密库位数量（不泄露）
- **保密库位清单**：原型阶段以示例占位（毒麻库、特殊材料库），代码中标注 TODO，后续替换为真实清单
- 页面不加"部分数据未显示"类提示，保密库位连存在性都不暴露

## 技术栈

沿用现有架构：原生 HTML + 原生 JS 前端原型（页面对象模式），无框架、无新依赖。

## 实现方案

### 1. `V3/js/data.js`：新增保密库位配置（示例占位）

在文件顶部常量区新增：

```js
// ===== 保密库位配置（权限不下放给 MES，库存查询页完全不可见）=====
// TODO: 示例占位，后续替换为真实保密库位清单
const CONFIDENTIAL_STORAGE_LOCS = ['1000|2010', '1000|3003'];
```

- 值与库位下拉/库存行的 `factory|storageLoc` 格式一致（如 `1000|2010` = 综合库-毒麻库，`1000|3003` = 综合库-特殊材料库，均已从 `T001L_STORAGE_LOCATIONS` 确认存在）
- `main.html` 第 566 行先加载 `data.js`、第 577 行后加载 `spare-parts-stock.js`，加载顺序满足引用要求

### 2. `V3/js/pages/spare-parts-stock.js`：保密库位完全不可见

**（a）新增判断方法**（遵循现有 `_xxx()` 方法模式）：

```js
_isConfidential(factory, storageLoc) {
  return CONFIDENTIAL_STORAGE_LOCS.includes(factory + '|' + storageLoc);
}
```

**（b）库位筛选下拉动态生成**：将 render() 中第 52-70 行硬编码的 16 个 option 抽取为常量数组 `STORAGE_LOC_OPTIONS`（value/text 结构，value 形如 `1000|1001`，text 形如 `1001 (综合库-成品库)`），并补入 `1000|2010`、`1000|3003` 两项保密示例；render() 中动态生成 option HTML 时过滤掉 `_isConfidential` 为真的项。

**（c）数据源过滤（共 4 处）**：保密过滤只作用于数据来源，聚合逻辑零改动——

- `render()`（第 29 行）：`this.filtered = sparePartsStockData.filter(r => !this._isConfidential(r.factory, r.storageLoc));`
- `init()`（第 111 行）：同上
- `search()`（第 303 行 filter 回调开头）：`if (this._isConfidential(row.factory, row.storageLoc)) return false;`
- `reset()`（第 327 行）：同上

由于 `_aggregate()`（库位汇总）与 `_aggregateByPlant()`（工厂汇总）均基于已过滤的 `this.filtered`，工厂层级总量自动排除保密库位数量，无需修改聚合与表格渲染逻辑。

## 关键决策

- **完全不可见**：不加任何"部分数据未显示"提示，不暴露保密库位存在性
- **不动共享数据源**：`sparePartsStockData` 同时被 `sp-purchase.js`（1480 行）与 `safety-stock-alert.js`（87 行）引用，**不得**向其中新增保密 demo 数据行，保密过滤只做在库存查询页内部，避免保密物资泄露到其他页面
- **过滤前置**：在数据源层过滤而非渲染层过滤，一处过滤三档（summary/plant/batch）全生效，杜绝回归
- 影响面仅两个文件，其他页面（安全库存预警、采购）不涉及库位级展示，本次不改
