## 需求概述

优化库存查询页「显示类型」下拉的 3 个选项，使其按**层级从粗到细**排列并配以清晰的层级文案：

1. 只显示到**工厂层级**
2. 显示到**工厂 + 库存地点**级别（批次汇总）
3. 显示到**工厂 + 库存地点 + 批次**层级（最细）

## 核心要求

- 3 个选项顺序调整为：工厂层级 → 工厂+库存地点 → 工厂+库存地点+批次
- 选项文案精炼且体现层级递增关系
- 仅调整下拉选项的**顺序与文案**；内部 value（`plant`/`summary`/`batch`）必须保留，聚合逻辑、表格渲染分支零改动
- 默认选中项保持「工厂+库存地点」（value=`summary`），与现有 reset() 重置行为一致

## 功能对照（现有档位与新文案映射）

- `plant`（工厂汇总档，含安全库存红绿灯）→ 新文案「工厂层级」
- `summary`（库位汇总档，批次聚合、安全库存灰色参考）→ 新文案「工厂+库存地点（批次汇总）」
- `batch`（批次明细档，原样展示）→ 新文案「工厂+库存地点+批次（明细）」

## 技术栈

沿用现有架构：原生 HTML + 原生 JS 前端原型（无框架），页面对象模式。本次为纯展示层文案/顺序微调，不引入任何新依赖。

## 实现方案

### 修改目标（唯一文件）

`V3/js/pages/spare-parts-stock.js` 第 71-75 行「显示类型」下拉：

```html
<div class="filter-group"><label>显示类型</label><select id="spDisplayType">
  <option value="plant">工厂层级</option>
  <option value="summary" selected>工厂+库存地点（批次汇总）</option>
  <option value="batch">工厂+库存地点+批次（明细）</option>
</select></div>
```

### 关键决策

- **保留 value 标识不变**：`plant`/`summary`/`batch` 被 `init()`、`search()`、`reset()`、`renderTable()` 依赖，只调整 option 的**显示顺序与文本**，聚合分发逻辑零改动，杜绝回归风险。
- **顺序与层级对齐**：由原「summary→plant→batch」调整为「plant→summary→batch」，与用户描述的 1→2→3 层级递增一致。
- **默认选中不变**：`selected` 仍落在 `summary`（工厂+库存地点），`reset()` 重置值 `'summary'` 无需改动，行为与之前完全一致。
- **文案风格**：贴合用户极简商务风偏好，选项文本无多余修饰；「（批次汇总）」「（明细）」后缀帮助用户理解各档粒度差异。

### 影响面

- 无逻辑变更，`_aggregate()`、`_aggregateByPlant()`、`renderTable()` 三档分支、图例显隐均不受影响。
- 无其他文件引用该下拉选项文案（已确认 `spDisplayType` 仅在 spare-parts-stock.js 内出现）。
