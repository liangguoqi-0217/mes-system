## 2. 模块概述

### 2.1 模块定位

车间领退料与库存记账模块整合了原先分散的库存相关入口，统一收口到一级菜单「库存管理」下，包含两类业务：

1. **预留单据**（领料单、退料单、入库单、预留过账）：以 **SAP 预留单（Reservation）** 为业务基础。MES 创建预留单后调用 SAP 创建预留接口，**SAP 返回预留编号后 MES 才将预留信息写入自建表**；修改同样需等待 SAP 反馈成功后再回写本地。
2. **库存记账**（统一入口，创建时选择 6 种记账类型）：面向车间用户在**本车间库存地点有物料库存的前提下**直接对库存进行记账（MIGO 直过账），**与预留无关**，不创建预留单。

### 2.2 核心流程

```
① 预留单据（领料/退料）：
MES 创建单据 → 调 SAP 创建预留接口 → SAP 返回预留编号 → MES 写入自建表
    → 跨车间场景：A 车间创建预留，B 车间对预留执行过账（调 SAP 过账接口）→ 返回物料凭证号

② 库存记账（6 种类型）：
车间用户 → 选择记账类型 → 填写物料/数量/库位 → 调 SAP 过账接口 → 返回物料凭证号 → MES 写入自建表
```

### 2.3 范围边界

- **在 MES 管理**：领料单、退料单、入库单的创建/查看/弹窗内编辑；预留的跨车间过账执行；6 种库存记账类型的直接过账
- **不在 MES 管理**：SAP 侧的预留创建、修改、过账的真实 BAPI 调用（当前阶段为 `SAP_MOCK` 模拟接口层，对接真实后端时仅替换 `js/core/sap-mock.js` 即可）
- **与预留无关**：库存记账 6 种类型均为 MIGO 直过账，不创建预留单，不进入预留过账流程
- **审批流**：预留单据与库存记账均无审批流

### 2.4 菜单结构（整合后）

一级菜单「库存管理」下二级分组：

| 二级分组 | 页面 | 页面对象 | 说明 |
|---|---|---|---|
| 预留单据 | 领料单 | `SpIssue` | 4 种创建方式 |
| 预留单据 | 退料单 | `SpReturn` | 3 种创建方式 |
| 预留单据 | 入库单 | `SpReceipt` | 成品入库，单一创建表单 |
| 预留单据 | 预留过账 | `SpReservationPost` | 跨车间预留执行过账 |
| 库存记账 | 库存记账 | `SpStockPost` | 统一入口，6 种记账类型 |
| 库存记账 | 物料凭证冲销 | `MaterialDocReversal` | 汇总所有已过账物料凭证，反向冲销 |
| 物料主数据 | 物料主数据 | `MaterialMaster` | 物料主数据维护 |
| 物料主数据 | 批次特性 | `BatchChar` | 双 Tab：批次特性修改 / 修改记录 |
| 保留 | 库存查询与预警（库存查询/安全库存预警）、采购申请管理 | — | 备件领用已删除，功能并入领料单 |

## 3. 用户场景与入口

### 3.1 目标用户

- 车间领料员、退料员：创建领料/退料预留单据
- 车间库管员：成品入库、执行预留过账、库存记账（库位转移/报废/差异调整/客供料收发/投料）
- 跨车间场景：A 车间创建预留，B 车间（收货车间）对预留执行过账

### 3.2 创建入口（方式选择弹窗）

所有「创建」按钮点击后**不直接跳转表单**，先弹出「选择方式」卡片弹窗，选择后进入对应表单：

#### 领料单（4 种）

| 序号 | 创建方式 | 移动类型 | 说明 |
|---|---|---|---|
| 1 | 领取即消耗-内部订单 | 261 | 创建 261 预留，领料后消耗至内部订单 |
| 2 | 领取即消耗-成本中心 | 201 | 创建 201 预留，领料后消耗至成本中心 |
| 3 | 领至暂存间 | 311 | A 库位 → B 库位转移预留，不填流程订单 |
| 4 | 按生产指令领至暂存间 | 311 | 按流程订单领料至暂存间，需填写流程订单编号 |

#### 退料单（3 种）

| 序号 | 创建方式 | 移动类型 | 说明 |
|---|---|---|---|
| 1 | 从内部订单退料 | 262 | 创建 262 预留，退回至内部订单（对应领料方式①部分消耗后） |
| 2 | 从成本中心退料 | 202 | 创建 202 预留，退回至成本中心（对应领料方式②） |
| 3 | 基于现有库存退料 | 262 | 基于现有库存直接退料回仓，不关联订单/成本中心 |

#### 入库单（1 种）

成品入库：按生产订单入库，填写生产订单号、物料、数量、批次、目标库位，单一表单，无方式选择弹窗。

#### 预留过账（0 种，非创建）

展示待过账预留列表，B 车间选择预留后在「查看」弹窗内执行过账。

#### 库存记账（6 种）

| 序号 | 记账类型 | 移动类型 | 说明 |
|---|---|---|---|
| 1 | 库位转移 | 311 | 同一工厂内 A 库位 → B 库位转移 |
| 2 | 库存报废 | 551 | 物料报废记账，需填报废原因 |
| 3 | 库存差异调整 | 561/562 | 盘点差异、手工调整（561=盘盈/562=盘亏） |
| 4 | 客供料收发 | K | 客供料收料 / 消耗记账 |
| 5 | 内部订单投料 | 261 | 车间库存直接消耗至内部订单（不建预留） |
| 6 | 成本中心投料 | 201 | 车间库存直接消耗至成本中心（不建预留） |

> **业务区分说明**：领料方式①②（建预留）与 库存记账类型⑤⑥（不建预留）**不重复**。前者是"拿物料走 + 建预留"（261/201 预留）；后者是物料已在车间，直接使用 MIGO 按相应移动类型消耗，**不创建预留**。

## 4. 数据模型

### 4.1 领料单（spIssueData，表前缀 PL-）

| 字段名 | 类型 | 必填 | 说明 |
|---|---|---|---|
| docNo | CHAR | 是 | 单据号，`PL-YYYYMMDD-NNN` 自动生成 |
| issueType | CHAR | 是 | 领料方式（consume-internal-order / consume-cost-center / staging-move / staging-process-order） |
| moveType | CHAR | 是 | 移动类型（261 / 201 / 311），由方式自动带出 |
| reservationNo | CHAR | 是 | SAP 预留编号，SAP 创建接口返回后回填 |
| plant | CHAR:4 | 是 | 工厂，默认 1000 |
| issueLocation | CHAR | 是 | 发出库位（下拉：A01原料仓 等） |

| internalOrderNo / costCenter / processOrderNo | CHAR | 条件 | 三种方式对应必填其一 |
| issueDept / applicant | CHAR | 是 | 请领部门、申请人 |
| issueDate | DATE | 是 | 领料日期 |
| status | CHAR | 是 | 草稿 / 待同步 / 已同步 / 部分过账 / 已完成 |

| chars[] | ARRAY | 是 | 特性：charCode、charName、charValue（当前值）、unit |
| updateBy / updateTime | CHAR | 是 | 最近修改人、最近修改时间 |

| 字段名 | 类型 | 必填 | 说明 |

| charCode / charName / unit | CHAR | 是 | 特性编码、特性名称、单位 |

### 4.7 物料凭证冲销（跨来源汇总）

汇总以下已过账来源中 `materialDocNo` 非空的行项目，扁平行字段：

| 字段名 | 说明 |
|---|---|
| docNo | 来源单据号 |
| sourceType | 来源类型：库存记账 / 入库单 / 预留过账 |
| materialDocNo | SAP 物料凭证号 |
| moveType | 原移动类型（自动带出） |
| matCode / matName / qty / unit / batch | 物料行项目 |
| factory / location | 工厂、库位 |
| postDate | 过账日期 |
| status | 已过账 / 部分过账 / 已冲销 |
| reversalDocNo | 冲销凭证号，冲销成功后回填 |

> 冲销后同步回写源单据数组（spStockPostData / spReceiptData / spReservationData）对应元素：`status='已冲销'`、`reversalDocNo=冲销凭证号`，保证单据页与冲销页状态联动。

## 5. 功能需求

### 5.1 领料单

**流程：**
1. 点击「创建领料单」→ 弹出方式选择弹窗（4 种卡片，见 3.2）
2. 选择方式 → 进入对应表单（条件字段随方式联动显示/隐藏）
3. 添加行项目（最少 1 行，行项目号 10/20/30… 递增）→ 点击「提交」
4. 调 SAP 创建预留接口（`SAP_MOCK.createReservation`）→ 展示 loading 层「正在与 SAP 同步，请等待…」
5. SAP 返回预留编号 → MES 将单据（含 reservationNo）写入自建表 → 刷新列表
6. SAP 失败 → 错误弹框（重试 / 取消），重试则重新调 SAP

**表单字段联动：**

| 创建方式 | 展示字段 |
|---|---|
| 领取即消耗-内部订单 | 发出库位 + 内部订单号（必填） |
| 领取即消耗-成本中心 | 发出库位 + 成本中心（必填） |
| 领至暂存间 | 发出库位 + 目标库位（必填），无订单字段 |
| 按生产指令领至暂存间 | 发出库位 + 目标库位 + 流程订单号（必填） |

**查询条件：** 单据号、领料类型（4 种）、发出库位、请领部门、状态。

**列表：** 操作列仅「查看」按钮（`btn btn-blue btn-sm`）；编辑入口在查看弹窗内。

**查看/编辑弹窗：** 大弹窗（98vw / max-height 98vh），抬头 `detail-grid` 卡片网格纯文本展示，行项目表格；「编辑」→ 切换编辑模式（行项目原位 `<input>`），抬头字段不可修改（隐藏域保留）；「提交修改」→ 调 `SAP_MOCK.updateReservation` → SAP 反馈成功后回写本地。

### 5.2 退料单

- 结构与领料单一致；创建方式 3 种（见 3.2），对应"领料部分消耗后"的退回场景
- 表单提取内部订单号 / 成本中心（按方式必填其一），可选填关联领料单号 refDocNo
- 创建/修改均走 SAP 预留接口（`SAP_MOCK.createReservation` / `updateReservation`），SAP 反馈成功后才写入本地
- 查询条件：单据号、退料类型（3 种）、退入库位、退料部门、状态
- 列表操作列仅「查看」，编辑在弹窗内

### 5.3 入库单（成品入库）

- 单一创建表单，无方式选择弹窗：生产订单号、物料行项目、数量、**批次（必填）**、目标库位、入库日期、创建部门、申请人
- 提交 → 调 `SAP_MOCK.postGoodsMovement`（移动类型 101）→ 返回物料凭证号 → 状态置「已过账」
- 支持「保存草稿」：不调 SAP，状态「草稿」，可后续编辑提交
- 查询条件：单据号、生产订单、目标库位、状态
- 列表操作列仅「查看」，编辑在弹窗内

### 5.4 预留过账（跨车间）

- 展示待过账预留列表（来源：A 车间创建的领料/退料预留），突出「发出车间 → 收货车间」关系（sourceDept → targetDept）
- 查询条件：预留号、发出车间、收货车间、状态（待过账 / 部分过账 / 已过账）
- 列表操作列仅「查看」；「过账」按钮位于查看弹窗内部
- **过账执行：**
  1. 查看弹窗内点击「执行过账」→ 弹出过账表单（过账日期、过账人必填）
  2. 每行行项目显示可过账数量输入框（最大 = qty − postedQty），默认整行待过账量，可修改
  3. 校验过账总量 > 0 → 调 `SAP_MOCK.postGoodsMovement` → 返回物料凭证号
  4. 回写本地 postedQty；全部行过账完成 → 状态「已过账」，否则「部分过账」
- 状态徽章：待过账（黄）/ 部分过账（蓝）/ 已过账（绿）

### 5.5 库存记账

- 统一入口：点击「创建记账」→ 弹出方式选择弹窗（6 种类型卡片，3 列网格）
- 选择类型 → 进入对应表单，类型专属字段联动显示：

| 记账类型 | 专属字段 |
|---|---|
| 库位转移 | 目标库位（必填） |
| 库存报废 | 报废原因（必填） |
| 库存差异调整 | 调整方向（盘盈/盘亏）+ 调整原因 |
| 客供料收发 | 收发方向（收料/消耗） |
| 内部订单投料 | 内部订单号（必填） |
| 成本中心投料 | 成本中心（必填） |

- 提交 → 调 `SAP_MOCK.postGoodsMovement` → 返回物料凭证号 → 状态「已过账」
- 列表按类型筛选（下拉 6 种 + 全部），类型徽章列（6 种类型各配一色），状态徽章（草稿灰 / 已过账绿 / 已冲销红）
- 列表操作列仅「查看」，编辑在弹窗内（编辑后重新过账，新物料凭证号覆盖）

### 5.6 公共列表规则

- 本地分页（默认 20 条/页）+ 筛选 + 重置
- 行项目在列表中聚合展示，明细在查看弹窗中以表格展开
- 操作列统一仅「查看」按钮（`btn btn-blue btn-sm`），保持界面清爽

### 5.7 批次特性（双 Tab 页面）

**Tab1「批次特性修改」：**
- 查询条件：工厂（下拉）、物料编码/名称（模糊）、批次号（模糊）
- 列表：批次号、物料编码/名称、工厂、库位、特性数、最近修改人、最近修改时间，操作列仅「查看」
- 查看弹窗（大弹窗）：批次抬头 `detail-grid` 纯文本 + 特性表格（每行特性可编辑当前值）+ 修改原因输入框（必填）
- 「保存修改」→ 校验有变更项且原因已填 → 调 `SAP_MOCK.changeBatchChar` → 成功后：
  - 回写 batchCharData 对应特性值、updateBy/updateTime
  - 每条变更写入 batchCharLogData（oldValue → newValue、原因）
- 无变更时提示「没有修改任何特性值」，不调 SAP

**Tab2「修改记录」：**
- 查询条件：批次号、特性名称（模糊）、修改人（模糊）、修改日期（date）
- 列表：记录号、批次号、物料编码、特性、原值→新值（原值删除线、新值绿色加粗）、修改人、修改时间、修改原因

**数据：** 批次特性数据基于物料主数据的「批次管理」启用的物料批次；修改记录不可手工编辑，仅由 Tab1 保存动作自动生成。

### 5.8 物料凭证冲销

- 汇总所有已过账来源（库存记账 / 入库单 / 预留过账）中 `materialDocNo` 非空的行项目，页面加载时一次性构建扁平数据，筛选走内存过滤
- 查询条件：物料凭证号、来源单据号、来源类型（下拉）、物料编码/名称（模糊）、状态（已过账/部分过账/已冲销）
- 统计栏：物料凭证行数 / 可冲销（已过账）/ 部分过账 / 已冲销
- 列表：物料凭证号、来源单据、来源类型（徽章）、移动类型（含文字说明）、物料、数量/单位、批次、工厂/库位、过账日期、状态徽章（已过账绿 / 部分过账蓝 / 已冲销红），操作列仅「查看」
- 查看弹窗：凭证抬头 `detail-grid` + 行项目表格；已冲销凭证展示冲销凭证号（红）；未冲销凭证弹窗底部提供「执行冲销」按钮
- 冲销弹窗：
  - 冲销移动类型由 SAP 按原移动类型**自动映射反向**（如 101→102），不允许手工修改
  - 冲销原因下拉必选（记账错误/数量错误/物料错误/库位错误/质量不合格退回/其他），可选填冲销说明
  - 「确认冲销」→ 调 `SAP_MOCK.reverseGoodsMovement` → 成功后：
    - 回写源单据数组对应元素 `status='已冲销'`、`reversalDocNo=冲销凭证号`
    - 刷新冲销页列表与统计

## 6. 交互规范

### 6.1 设计风格

沿用项目性冷淡/极简商务风：
- 中性灰背景（#F8FAFC / #F1F5F9）+ 白色卡片
- 单一强调色：深蓝 #1E3A5F（页头渐变、按钮、徽章底色）
- 状态用小面积语义色徽章：绿=成功/已过账、红=错误/已冲销、黄=待处理、蓝=部分过账、灰=草稿
- 无装饰性元素、无彩虹色块

### 6.2 创建方式选择弹窗

- 点击「创建」→ 弹窗（modal-xl，96vw）内卡片网格（2~4 列）
- 卡片含：图标、名称、说明文字、移动类型标签
- hover 微动效（轻微上浮 + 阴影）

### 6.3 弹窗规范

- 宽度尽量大（98vw, max-width 98vw），高度尽量大（max-height 98vh）
- body 不设额外高度限制，由 flex 撑满剩余空间，避免出现滚动条
- 弹窗内布局充分利用空间，表单字段分行排列
- 查看模式与编辑模式布局严格一致（抬头 detail-grid 纯文本 + 行项目表格），仅交互元素差异（input 替代文本）

### 6.4 SAP 调用反馈

- 调用期间显示 loading 层：深蓝旋转圈 + 「正在与 SAP 同步，请等待…」
- 失败：错误弹框（含错误信息 + 重试 / 取消按钮），重试重新调用
- 接口带 30s 超时保护

### 6.5 表单校验

- 必填项校验（抬头字段 + 行项目）
- 数量 > 0 校验
- 库位必选校验
- 批次必填校验（入库单）
- 过账数量不超过可过账量校验（预留过账）

## 7. 业务规则

| 规则编号 | 规则描述 |
|---|---|
| BR-01 | MES 创建/修改预留单据必须先调 SAP 接口，SAP 返回预留编号/反馈成功后 MES 才写入本地自建表 |
| BR-02 | SAP 接口失败时不允许落库，展示错误并提供重试 |
| BR-03 | 领料方式①② 与 库存记账类型⑤⑥ 业务不重复：前者"拿物料走+建预留"，后者"车间直接消耗不建预留" |
| BR-04 | 库存记账 6 种类型均为 MIGO 直过账，不创建预留单，不进入预留过账流程 |
| BR-05 | 跨车间场景：A 车间创建预留，B 车间（收货车间）对预留执行过账 |
| BR-06 | 预留过账逐行记录已过账数量（postedQty），支持部分过账 |
| BR-07 | 行项目号自动递增：10、20、30… |
| BR-08 | 行项目最少 1 行；数量必须 > 0 |
| BR-09 | 入库单批次（batch）必填；预留单据批次可选 |
| BR-10 | 所有列表操作列仅「查看」，编辑入口在查看弹窗内 |
| BR-11 | 所有多方式创建单据，「创建」按钮先弹方式选择弹窗，不直接跳表单 |
| BR-12 | 库存记账提交后不可直接删除，如记账错误走冲销 |
| BR-13 | 移动类型由创建方式/记账类型自动带出，不允许用户手工修改 |
| BR-14 | 批次特性修改必须填写修改原因，否则不允许提交 |
| BR-15 | 批次特性修改成功即自动生成修改记录（batchCharLogData），修改记录不可手工新增/编辑 |
| BR-16 | 物料凭证冲销移动类型由 SAP 自动映射反向（101→102、261→262、201→202、311→312、551→552、561→562），不允许手工修改 |
| BR-17 | 已冲销凭证不允许重复冲销；草稿/待同步状态无物料凭证号，不进入冲销列表 |
| BR-18 | 冲销成功后必须回写源单据状态为「已冲销」并记录冲销凭证号，保证各页面状态一致 |

## 8. 接口说明（SAP_MOCK 模拟层）

> 当前阶段全部为前端模拟实现，位于 `V3/js/core/sap-mock.js`，全局对象 `SAP_MOCK`，Promise 接口 + 人工延迟 + 随机失败分支。对接真实后端时**仅需替换该文件**，页面代码无需改动。

### 8.1 创建预留 `createReservation(payload)`

- **方向**：MES → SAP
- **触发时机**：领料单/退料单点击「提交」（创建）
- **入参**：单据抬头 + 行项目（方式、移动类型、工厂、库位、订单/成本中心、物料行等）
- **返回**：`{ ok: true, reservationNo: '1000000xxx' }`
- **失败率**：约 12%，失败返回 `{ ok: false, error }`

### 8.2 修改预留 `updateReservation(resNo, payload)`

- **方向**：MES → SAP
- **触发时机**：领料单/退料单查看弹窗内「提交修改」
- **入参**：预留编号 + 修改后数据
- **返回**：`{ ok: true }`
- **失败率**：约 10%

### 8.3 货物移动过账 `postGoodsMovement(payload)`

- **方向**：MES → SAP
- **触发时机**：预留过账「执行过账」、入库单「提交」、库存记账「提交」
- **入参**：移动类型、工厂、库位、物料行、数量等
- **返回**：`{ ok: true, materialDocNo: '49xxxxxx' }`
- **失败率**：约 8%

### 8.4 修改批次特性 `changeBatchChar(payload)`

- **方向**：MES → SAP
- **触发时机**：批次特性查看弹窗内「保存修改」
- **入参**：批次号、物料编码、修改原因、变更项数组（charCode/charName/unit/oldValue/newValue）
- **返回**：`{ ok: true, logNo: 'BCL-YYYYMMDD-NNN', changeBy, changeTime }`
- **失败率**：约 6%，失败返回 `{ ok: false, error }`（批次被锁定/被其他用户占用）

### 8.5 冲销物料凭证 `reverseGoodsMovement(payload)`

- **方向**：MES → SAP
- **触发时机**：物料凭证冲销弹窗内「确认冲销」
- **入参**：物料凭证号、来源类型、来源单据号、冲销移动类型（自动映射）、物料/数量/批次、冲销原因
- **返回**：`{ ok: true, reversalDocNo: '49xxxxxxxx', reverseMoveType }`
- **失败率**：约 8%，失败返回 `{ ok: false, error }`（凭证已存在冲销记录或不允许冲销）

### 8.6 公共能力

- `SAP_MOCK.showLoading(text)` / `SAP_MOCK.hideLoading()`：全局 loading 层（深蓝旋转圈）
- 所有接口含 30s 超时保护

### 9.2 状态流转

**预留单据（领料/退料）：**

```
草稿(灰) → 待同步(黄) → 已同步(蓝) → 部分过账(蓝) → 已完成(绿)
```

- 草稿：仅入库单支持（保存草稿不调 SAP）
- 待同步：本地已保存但 SAP 预留创建/修改未确认（异常状态）
- 已同步：SAP 预留编号已回填
- 部分过账：预留过账页已过账部分数量
- 已完成：全部行项目过账完成

**库存记账 / 入库单：**

```
草稿(灰) → 已过账(绿) → 已冲销(红)
```

> 已冲销为物料凭证冲销页执行冲销后的终态，冲销后不可再次冲销。

### 9.5 技术架构

```
main.js App.menu ─┬─ 预留单据分组 ─┬─ sp-issue.js 领料单
                  │               ├─ sp-return.js 退料单
                  │               ├─ sp-receipt.js 入库单
                  │               └─ sp-reservation-post.js 预留过账
                  ├─ 库存记账分组 ─┬─ sp-stock-post.js 库存记账
                  │               └─ material-doc-reversal.js 物料凭证冲销
                  └─ 物料主数据分组 ─┬─ material-master.js 物料主数据
                                    └─ batch-char.js 批次特性（双 Tab）

sp-issue / sp-return / sp-reservation-post ──→ SAP_MOCK 模拟接口层 ──→ 本地自建表(模拟数据)
sp-stock-post / sp-receipt / sp-reservation-post ──→ material-doc-reversal.js（汇总凭证 + 冲销回写）
```

> 脚本加载顺序：`material-doc-reversal.js` 必须排在所有 sp-* 单据脚本之后（依赖其顶层 const 数据数组）；`batch-char.js` 排在 `material-master.js` 之后。

- 页面对象 `{ render() / init() }` 由 `main.js` 的 `App.pageMap` 注册挂载
- 模拟数据数组置于各页面文件底部（`const spXxxData = [...]`）
- 样式沿用 `V3/css/common.css`（性冷淡商务风样式库）
