# 样品台账 设计评审文档

> 版本：v2.0（对应代码 `V3/js/pages/sample-ledger.js`，菜单/路由见 `V3/js/main.js`）
> 依据：受控文件 ZSX-SMP-CNAS-023 等留样/样品管理规程；流程原型 `V3/qc-sample-flow.html`
> 完整功能规格见《样品管理PRD.md》，本文件聚焦**业务逻辑设计思路 + 界面设计原则**，并给出希望评审重点挑战的问题清单。
> 评审日期：2026-11-05

---

## 1. 定位与一句话概括

**样品台账 = QC 样品室的"实物账本"**：每一瓶东西从哪来、放在哪、谁动过、怎么没的，一屏可查；留样环节与 SAP 库存对齐。

它回答的是"**实物**"的问题；"检验做没做完、结论合不合格"归检验批管理。两者靠检验批号关联。

## 2. 业务对象：一个台账，两类东西

QC 样品室里实际存在的只有两种实物，历史上分属两个页面，现合并为**一张表**，用 `category` 区分：

| | 留样 RETENTION | 检验样品 INSPECT |
|---|---|---|
| 来源 | 生产/入库时按物料规则留存 | 请验取样送来检验 |
| 目的 | 留档备查、稳定性观察、投诉仲裁 | 完成检验、支撑放行 |
| 编号 | `LS-工厂-年+流水` | `类别代码-年-月-流水`（14 类：YC/YF/NBC/WBC/CP/ZJ/WD/GS/KQ/HJ/YZ/WT/KY/QT） |
| 到期规则 | 有效期后 1 年 / 6 个月 / 放行后 3 年（物料规则配置） | 无固定期限，检毕即可处置 |
| 去向 | 只能销毁 | 销毁 / 返还送检方 / 检验消耗 |
| 合规要求 | 销毁需**双执行人 + 见证人** | 单执行人 |
| SAP | 登记过账 **311**（生产库位→留样库位），销毁过账 **551**（报废） | 不是库存，**不过账** |
| 观察 | 按物料规则频次定期观察，异常可发起质量异常单 | 无 |

**合并的理由**：两类实物管理动作同构（登记→落位→调用→归还→处置），管理动作只有一套状态机；对用户，查东西只去一个地方；对维护，只养一套逻辑。**不合并的代价**（被放弃的方案）：继续两页并存，则位置树、调用/归还、处置逻辑要写两遍，且"留样到期"和"检验样品过期"两套口径容易漂移。

## 3. 核心业务逻辑

### 3.1 状态只回答"东西在哪"——4 态状态机

```
待入库 REG ──入库上架──> 在库 STORED ──调用──> 借出中 CALLED ──归还──> 在库
                 │                                  │
                 └──────────处置登记────────────────┴──> 已处置 DISPOSED（终态只读）
```

**关键决策：状态粗化为 4 态，到期/待观察/待处置一律不做成状态。**

理由：
1. 到期是"日期算出来的结果"，不是生命周期阶段。做成状态必须靠定时任务或人工刷新，一旦没人刷，状态与日期脱节，台账开始撒谎。
2. "待观察""待处置"是叠加在"在库"之上的**事实标记**，与"借出中"这类物理状态不在一个维度上，做成互斥状态会出现"一个样品既过期又借出"的表达困境。
3. v1 的"已消耗/已返还/已销毁"三个终态合并为 `DISPOSED` + `disposal.mode` 字段——处置方式是处置记录的属性，不是一种独立的"存在状态"。

腾出来的工作清单全部降级为**派生筛选**（实时计算，永不过期）：

| 原状态 | 现表达 |
|---|---|
| 即将到期 / 已到期 | 到期日列高亮（红"已超期 x 天"/黄"x 天后到期"）+ 筛选「已过期 / ≤30 天 / ≤90 天」 |
| 待观察 | 观察任务无实际完成日期 + 筛选「待观察（留样）」 |
| 待处置 | `pendingDisposal` 标记（唯一自动产生的待办：归还时勾"破损/污染"自动挂上）+ 筛选「待处置」 |

### 3.2 动作即事实登记（MES 不做审批）

每个动作登记的是**已发生的事实**，审批在纸质/eQMS 完成。动作矩阵两类同构：

| 状态 | 可用动作 |
|---|---|
| 待入库 | 上架（从位置树选位） |
| 在库 | 位置变更 · 调用 · 观察（仅留样）· 处置 |
| 借出中 | 位置变更 · 归还 |
| 已处置 | 无（只读终态） |

动作要点：

- **登记**：三种入口——留样登记（按"质量主数据→留样规则"自动带出留样量/保存条件/期限/观察频次，可覆盖，登记后过账 311）、从检验批带出（物料批次自动带入）、手动登记（环境监测/验证样等无请验单场景）。
- **调用/归还**：记录领取人/用途/数量/时间；归还时登记"完好 / 破损"。破损 → 自动挂待处置标记，等销毁登记。调用只记台账，不做 SAP 移动。
- **观察**：按频次生成 N 次任务（planDate 预排），逐次录入；结果 NG 可一键发起质量异常单，异常单号回写观察记录。观察全部完成是到期销毁的前置事实。
- **处置**：留样销毁表单强制双执行人 + 见证人 + 销毁方式（焚烧/化学/撕碎/高压灭菌），登记后生成 SAP 551 报废凭证号；检验样品三选一，返还时记录返还对象（物流部库房/供应商），消耗则余量清零直接转已处置。

### 3.3 位置是主数据，不是字符串

位置树为公共核心模块（`core/sample-locations.js`），层级：**样品间(房间) → 冰箱/柜 → 层 → 盒（→ 行列位）**，每节点带温区（常温/阴凉/冷藏/冷冻）。

- 所有存放位置必须从**位置选择弹窗**（级联自顶向下）选择，禁止手输位置编码——因为"找样品"每天发生几十次，位置必须可反查、可统计。
- 位置树采用**供应商模式**做占用统计：各台账页注册 provider 返回自己的占用位置，core 只聚合不依赖页面。位置管理页树上直接显示每个节点的在库占用数，支持"占用反查"和停用前校验（含子孙节点无在库占用才可停用）。
- 兼容历史：留样室 A/B/C 旧字段（room/cabinet/shelf）由位置树按名称自动匹配回写 `locCode`。

### 3.4 SAP 集成口径

| 环节 | 留样 | 检验样品 |
|---|---|---|
| 登记 | 311（转储到留样库位），回写物料凭证号 | 不过账 |
| 销毁 | 551（报废），回写凭证号 | 不过账 |
| 调用/归还 | 不过账 | 不过账 |

原则：**留样是库存，动库存就要有凭证；检验样品不是库存，MES 只管实物行踪。** 凭证号在详情页签展示，不做独立凭证页。

### 3.5 数据流总览

```
检验批 ──带出物料/批次/批号──> 检验样品登记
留样规则（质量主数据）──带出留样量/期限/频次──> 留样登记
位置树（公共主数据）──引用──> 两类样品落位
样品台账 ──占用统计/反查──> 位置管理
留样登记/销毁 ──311/551──> SAP（仅留样）
样品台账 ──"已登记"单向可见──> 检验批（不回写）
质量异常单 <──一键发起── 观察异常
```

## 4. 界面设计

### 4.1 信息架构

```
质量管理
 ├─ 质量主数据：… / 留样规则 / 位置管理 / …
 ├─ 质量检验：检验批管理 / …
 └─ 样品管理：样品台账          ← 唯一台账入口
```

配置类入口（留样规则、位置管理）一律收进"质量主数据"菜单，台账页头只留主操作「+ 样品登记」。理由：台账是**高频作业页**，页头放低频配置按钮会稀释主操作。

### 4.2 列表布局

**列**（单屏 9 列，最小宽度 1360px）：

样品编号（等宽字体）｜类别（徽章）｜物料｜来源批次｜数量/余量｜存放位置（面包屑）｜到期日｜状态｜操作

设计取舍：
- **类别只用一枚徽章**：留样标"留样"，检验样品直接标类别全称（如"原辅料"）——类别代码已在编号前缀里（YF-2026-05-018），不重复显示。
- **存放位置只显示面包屑**（留样室A / A-03柜 / 2层），位置编码下沉到详情——编码是给系统用的，人读路径。
- **到期日列承担全部紧迫度信号**：日期 + 红色"已超期 x 天"/ 黄色"x 天后到期"，一列说清，不做单独的到期状态列。
- **状态列允许叠一枚小标记**："待观察""待处置"，与状态徽章同单元格，这俩是可筛选的工作标记而非状态。

**筛选**：第一行高频项（工厂/类别/关键字/状态），低频项（位置/检验批号/来源批次/剩余天数/登记日期区间）收进"更多条件"。状态筛选额外含两个派生项「待观察（留样）」「待处置」。

### 4.3 行内操作：全集常显（关键交互决策）

**每行固定 7 个按钮，完全一致，不按状态显隐或置灰：**

```
上架 · 变更 · 调用 · 归还 · 观察 · 处置 · 查看
```

- 当前状态不支持的操作，点击时经统一分发 `_act` 拦截，toast 告知原因：`样品 LS-2001-2408005 状态为「已处置」，不支持「调用」操作`。
- **为什么不用按状态显隐**（用户明确决策）：显隐导致每行按钮数量、列宽跳动，列表视觉混乱；全集常显让用户建立稳定的空间记忆，且操作入口可预测。这与检验批管理模式一致，已固化为前端规范 `UI-SPL-03`。
- 操作列定宽 320px（最宽 7 键单行放下），不参与自适应挤压。

### 4.4 查看弹窗（只读）

顶部：位置面包屑横幅（未入库则黄色提示条）+ 状态徽章（终态加"终态只读"）。**不放操作按钮**——操作在行上，弹窗里再放一遍是两份入口两份维护。

5 个页签：
1. **基本信息**：编号/状态/类别/工厂/物料/批次/数量余量/保存条件/有效期/到期日/登记与上架时间；留样额外展示期限规则、观察频次、标签号、SAP 311 凭证。
2. **位置与移动**：当前位置 + 移动流水（时间/原位置/新位置/操作人/原因，原因如"温度异常转移"）。
3. **调用记录**：调用单号/领取人/用途/数量/领用时间/归还时间/归还完好性。
4. **观察记录**（仅留样渲染）：按次序列出计划/实际/观察人/项目/结果/备注，异常行带质量异常单号；页签内保留"录入观察 →"文字入口（弹窗内唯一保留的动作入口，属于页签内的自然动线）。
5. **处置记录**：处置方式/日期/数量 + 按 mode 显隐的字段（销毁：单号/方式/双执行人/见证人/原因 + SAP 551 凭证；返还：对象；消耗：经办人）。

### 4.5 表单设计

- 登记先弹**方式选择卡片**（留样登记 / 从检验批带出 / 手动登记）再进表单——三种来源字段差异大，一张表单装不下。
- 处置同理：检验样品先弹三选一（销毁/返还/消耗），留样只有销毁直接进表单。
- 表单内不写解释性文案；只保留两条**操作后果提示**："登记后过账 SAP 311"、"登记后过账 SAP 551"（仅留样渲染）——这不是界面说明，是业务后果，删了会踩坑。

### 4.6 界面文字原则

不加解释性小字与副标题，列头和结构自己说话。保留的小字都有明确功能：到期紧迫度（唯一的期限信号）、待观察/待处置标记（可筛选）、阻断提示（交互反馈）。

## 5. 明确不做的事（及理由）

| 不做 | 理由 |
|---|---|
| 到期推送 / 角标 | 到期处置有大量人为判断（延长期限、提前销毁），推送制造"狼来了"；分档高亮+筛选够用 |
| 检毕转留样 | 留样在生产/入库环节留，检验样品检毕只有三去向，不混淆两条链路 |
| 审批流 | MES 是事实系统不是审批系统；审批在纸质/eQMS |
| 条码/扫码硬件 | 演示阶段不做，位置用级联树选择 |
| 稳定性样入台账 | 归稳定性模块（方案/计划/数据），不混入 |

## 6. Mock 数据场景覆盖（供评审走查）

台账内置 31 条演示数据（留样 15 / 检验样品 16），覆盖：

- **状态 4 态**：待入库 3（含外部委托样，无物料编码）/ 在库 22 / 借出中 2 / 已处置 4
- **处置三方式**：销毁（含 551 凭证）、返还送检方（不过账）、检验消耗
- **待处置标记**：留样破损归还（S013）、检验样品破损归还（P012）
- **到期分档**：已超期（-127 / -339 / -15 天）、≤30 天（26/7/4 天）、≤90 天（57/57/31 天）、无有效期（"—"，不参与到期筛选）
- **观察闭环**：正常待观察、异常已挂质量异常单、全部完成（无标记对照）
- **位置轨迹**：多次移库（4 条含"温度异常转移"）、盒级深位置、未入库
- **调用形态**：未归还（借出中）、多次调用已归还、破损归还

## 7. 请评审重点挑战的问题

1. **4 态够不够**：如果未来出现"待请验退回""样品转移给注册部长期保管"这类新场景，是继续用 4 态 + 标记，还是需要扩状态？（当前答案：扩标记，不动状态机。）
2. **全集常显 vs 显隐**：7 键常显在窄屏/大数据量下是否仍然合适？是否需要支持列配置隐藏低频键（如"变更"）？——与检验批管理的一致性 vs 界面密度，请权衡。
3. **检验样品是否需要有效期**：当前外包材/外部委托无有效期（"—"），成品原料有。是否存在类别默认规则（如 NBC/WBC 默认无）？
4. **破损归还自动挂"待处置"**：是否应该同时冻结"调用/变更"操作（当前仍可点，会被允许，因为有位置）？业务上破损样品还允许移位吗？
5. **观察频次与到期日的关系**：观察任务按固定次数预排（如 3 次/每 12 个月），未强制校验"最后一次观察日期 ≤ 到期日"。需要强校验吗？
6. **SAP 口径**：留样调用（复测取用）会减少留样实物量但不过账，实物与 SAP 库存会渐行渐远。是否需要在归还 NG（破损）时也触发 551 部分报废？当前设计：销毁登记时一次性 551 清零。
7. **编号不统一**（LS vs 类别代码）：是否值得推动统一编号规则，还是保持现状靠搜索框兼容？
